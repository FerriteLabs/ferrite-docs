With v0.2.0 shipped — bringing stable HybridLog storage, primary-replica replication, and 92% Redis test suite compatibility — we're now focused on the features that make Ferrite production-ready at scale. Here's what's coming in v0.3.0.

<!-- truncate -->

## The v0.3.0 Theme: Enterprise & Observability

Where v0.2.0 was about core hardening (correctness, persistence, compatibility), v0.3.0 is about the features teams need before deploying Ferrite in production: **cluster mode stability**, **observability**, and graduating our most-requested extension features from beta to stable.

## Cluster Mode → Stable

Cluster mode has been in beta since v0.1.0, and we've been running it internally with automated Jepsen-style testing. For v0.3.0, we're graduating it to stable with:

- **Automated failover** with configurable detection thresholds
- **Live resharding** without client-visible downtime
- **Jepsen linearizability verification** as part of CI
- **Gossip protocol hardening** based on edge cases found in chaos testing

If you've been waiting to deploy Ferrite in a clustered configuration, v0.3.0 is the release to target.

## Vector Search → Stable

Vector search has been one of our most popular beta features, powering semantic caching and RAG pipelines. In v0.3.0:

- **End-to-end server wiring** is complete — no more experimental feature flags needed
- **HNSW index performance** benchmarks published alongside Redis Stack comparisons
- **Hybrid search** combining vector similarity with keyword filters
- **Production-grade memory management** for large embedding collections

This means `VECTOR.CREATE`, `VECTOR.ADD`, and `VECTOR.SEARCH` graduate to stable, first-class commands.

## OpenTelemetry → Stable

Observability is non-negotiable for production. Our OpenTelemetry integration moves to stable with:

- **Distributed tracing** for cross-service request tracking
- **Metric export** to Prometheus, Datadog, New Relic, and any OTLP-compatible backend
- **Span attributes** on every command execution, including latency breakdown by storage tier
- **Pre-built Grafana dashboards** for memory tiers, query performance, streaming, and vector search

We've also added 6 operational runbooks covering common scenarios like high latency, disk full, replication lag, cluster failure, and backup failure.

## CDC & Event Streaming → Stable

Change Data Capture has been in beta with Kafka integration. For v0.3.0:

- **Reliable delivery guarantees** with configurable at-least-once and exactly-once semantics
- **Pipeline composition** — chain CDC events through transformation steps
- **Schema evolution** support for downstream consumers
- **Backpressure handling** when consumers fall behind

## Full-Text Search → Stable

The `ferrite-search` crate graduates with:

- **BM25 scoring** with configurable parameters
- **Auto-indexing** that infers searchable fields from your data
- **Query routing** across shards in cluster mode
- **Schema management** for structured search indexes

## What Else Is Coming

Beyond the graduation milestones, v0.3.0 includes:

- **Kubernetes Operator** CRD scaffolding and basic reconciliation loop
- **Expanded integration tests** for all extension crates
- **SDK improvements** across Rust, Python, Go, Node.js, TypeScript, Java, and .NET clients
