# LangChain Integration

Use Ferrite as a high-performance cache and vector store backend for [LangChain](https://python.langchain.com/).

## Overview

Ferrite integrates with LangChain as both an **LLM response cache** and a **vector store**, giving you:

- **Sub-millisecond cache lookups** — avoid redundant LLM API calls with Ferrite's in-memory tiered storage
- **Native vector search** — HNSW/Flat indexes for similarity search without a separate vector database
- **Redis protocol compatibility** — drop-in replacement using standard Redis-based LangChain components
- **Semantic caching** — match similar queries by meaning, not just exact string equality

The `ferrite-py` SDK (in `sdk/ferrite-py/`) provides the `Ferrite` client and `VectorStore` helper used throughout these examples.

## LLM Response Caching

Ferrite's `SEMANTIC.*` commands let LangChain cache LLM responses so repeated or similar prompts return instantly.

```python
import hashlib
import json
import os

from langchain_core.language_models import BaseChatModel
from langchain_openai import ChatOpenAI
from ferrite import Ferrite

# Connect to Ferrite (Redis-compatible)
cache = Ferrite(host="localhost", port=6379, db=0)

def cached_llm_call(
    llm: BaseChatModel,
    prompt: str,
    *,
    ttl: int = 3600,
    prefix: str = "llmcache",
) -> str:
    """Call an LLM with Ferrite-backed response caching."""
    key = f"{prefix}:{hashlib.sha256(prompt.encode()).hexdigest()}"

    # Check cache
    cached = cache.get(key)
    if cached is not None:
        return json.loads(cached)["response"]

    # Cache miss — call the LLM
    response = llm.invoke(prompt)
    cache.setex(
        key,
        ttl,
        json.dumps({"prompt": prompt, "response": response.content}),
    )
    return response.content


llm = ChatOpenAI(
    model="gpt-4o-mini",
    api_key=os.environ["OPENAI_API_KEY"],
)

# First call hits the API
answer = cached_llm_call(llm, "Explain the CAP theorem in two sentences.")
print(answer)

# Second call returns from Ferrite in < 1 ms
answer = cached_llm_call(llm, "Explain the CAP theorem in two sentences.")
print(answer)
```

### Semantic Caching

For fuzzy matching (e.g. "Explain CAP theorem" ≈ "What is the CAP theorem?"), use Ferrite's built-in semantic cache commands:

```python
from ferrite import Ferrite

cache = Ferrite(host="localhost", port=6379)

# Store with embedding vector (generated by your embedding model)
cache.execute_command(
    "SEMANTIC.SET",
    "What is the CAP theorem?",
    "The CAP theorem states that a distributed system can provide at most two of three guarantees...",
    "[0.12, 0.34, ...]",   # pre-computed embedding
    3600,                   # TTL in seconds
)

# Retrieve by similar text (requires server-side embedding provider)
result = cache.execute_command(
    "SEMANTIC.GETTEXT",
    "Explain CAP theorem",
    "THRESHOLD", 0.85,
)
```

## Vector Store

Use Ferrite's native vector indexes as a LangChain-compatible vector store for similarity search.

```python
import os
import struct
from typing import Any

from langchain_openai import OpenAIEmbeddings
from ferrite import Ferrite
from ferrite.vector import VectorStore


def embed_texts(texts: list[str], embeddings: OpenAIEmbeddings) -> list[list[float]]:
    """Generate embedding vectors for a list of texts."""
    return embeddings.embed_documents(texts)


# --- setup ---
client = Ferrite(host="localhost", port=6379)
store = VectorStore(client)
embeddings = OpenAIEmbeddings(
    model="text-embedding-3-small",
    api_key=os.environ["OPENAI_API_KEY"],
)

INDEX_NAME = "langchain_docs"
DIMS = 1536  # text-embedding-3-small output dimension

# Create a vector index in Ferrite
store.create_index(INDEX_NAME, dimension=DIMS, metric="COSINE")

# --- ingest documents ---
documents = [
    {"id": "doc1", "text": "Ferrite is a high-performance key-value store.", "source": "readme"},
    {"id": "doc2", "text": "Ferrite supports HNSW and Flat vector indexes.", "source": "docs"},
    {"id": "doc3", "text": "Tiered storage moves cold data from memory to disk.", "source": "architecture"},
    {"id": "doc4", "text": "Epoch-based reclamation enables lock-free concurrency.", "source": "architecture"},
]

texts = [d["text"] for d in documents]
vectors = embed_texts(texts, embeddings)

for doc, vec in zip(documents, vectors):
    store.add(INDEX_NAME, doc["id"], vec, {"text": doc["text"], "source": doc["source"]})

print(f"Indexed {len(documents)} documents into '{INDEX_NAME}'")

# --- query ---
query = "How does Ferrite handle concurrent access?"
query_vec = embeddings.embed_query(query)
results = store.search(INDEX_NAME, query_vec, k=2)

print(f"\nTop results for: '{query}'")
print(results)
```

## Retrieval Chain (RAG)

Combine Ferrite's vector store with an LLM to build a Retrieval-Augmented Generation pipeline.

```python
import os

from langchain_openai import ChatOpenAI, OpenAIEmbeddings
from langchain_core.prompts import ChatPromptTemplate
from langchain_core.output_parsers import StrOutputParser
from langchain_core.runnables import RunnablePassthrough
from ferrite import Ferrite
from ferrite.vector import VectorStore

# --- connections ---
client = Ferrite(host="localhost", port=6379)
store = VectorStore(client)
embeddings = OpenAIEmbeddings(
    model="text-embedding-3-small",
    api_key=os.environ["OPENAI_API_KEY"],
)
llm = ChatOpenAI(model="gpt-4o-mini", api_key=os.environ["OPENAI_API_KEY"])

INDEX_NAME = "rag_knowledge"
DIMS = 1536

# --- build the knowledge base ---
store.create_index(INDEX_NAME, dimension=DIMS, metric="COSINE")

knowledge = [
    "Ferrite uses a three-tier HybridLog: mutable region in memory, read-only region via mmap, and a disk region accessed through io_uring.",
    "The epoch-based reclamation system allows Ferrite to perform lock-free reads while safely reclaiming memory.",
    "Ferrite speaks the Redis protocol (RESP3) so any Redis client library can connect without changes.",
    "Vector indexes in Ferrite support HNSW and Flat algorithms with cosine, L2, and inner-product metrics.",
    "Semantic caching in Ferrite matches queries by meaning, reducing LLM API calls by 60-80%.",
]

vectors = embeddings.embed_documents(knowledge)
for i, (text, vec) in enumerate(zip(knowledge, vectors)):
    store.add(INDEX_NAME, f"kb:{i}", vec, {"text": text})


def retrieve(question: str, k: int = 3) -> str:
    """Retrieve the top-k relevant passages from Ferrite."""
    q_vec = embeddings.embed_query(question)
    results = store.search(INDEX_NAME, q_vec, k=k)

    # results is a list where items alternate: [count, key, fields, key, fields, ...]
    # Extract the text fields from the result set
    passages: list[str] = []
    if isinstance(results, (list, tuple)) and len(results) > 1:
        for item in results[1:]:
            if isinstance(item, (list, tuple)):
                for j in range(0, len(item), 2):
                    if item[j] == b"text" or item[j] == "text":
                        passages.append(
                            item[j + 1].decode()
                            if isinstance(item[j + 1], bytes)
                            else str(item[j + 1])
                        )
    return "\n\n".join(passages) if passages else "No relevant context found."


# --- RAG chain using LCEL ---
prompt = ChatPromptTemplate.from_template(
    """Answer the question based only on the following context.
If you cannot answer from the context, say so.

Context:
{context}

Question: {question}"""
)

rag_chain = (
    {"context": lambda x: retrieve(x["question"]), "question": lambda x: x["question"]}
    | prompt
    | llm
    | StrOutputParser()
)

# --- run ---
question = "How does Ferrite store data across memory and disk?"
answer = rag_chain.invoke({"question": question})
print(f"Q: {question}\nA: {answer}")
```

## Cost Savings Analysis

Combining Ferrite caching with LangChain dramatically reduces LLM API spend.

### Estimating Savings

The key formula:

```
Monthly savings = (cache_hit_rate) × (total_requests) × (avg_cost_per_request)
```

### Projected Costs

| Monthly requests | Cache hit rate | API cost without cache | API cost with Ferrite | Savings |
|-----------------|----------------|----------------------|----------------------|---------|
| 10,000 | 60% | $20 | $8 | **$12** |
| 100,000 | 70% | $200 | $60 | **$140** |
| 500,000 | 75% | $1,000 | $250 | **$750** |
| 1,000,000 | 80% | $2,000 | $400 | **$1,600** |

*Based on GPT-4o-mini at ~$0.002 per request (prompt + completion).*

### Tracking Costs at Runtime

```python
from dataclasses import dataclass, field
from ferrite import Ferrite


@dataclass
class CacheStats:
    hits: int = 0
    misses: int = 0
    cost_per_call: float = 0.002  # GPT-4o-mini average

    @property
    def total(self) -> int:
        return self.hits + self.misses

    @property
    def hit_rate(self) -> float:
        return self.hits / self.total if self.total else 0.0

    @property
    def money_saved(self) -> float:
        return self.hits * self.cost_per_call

    def report(self) -> str:
        return (
            f"Requests: {self.total}  |  "
            f"Hit rate: {self.hit_rate:.1%}  |  "
            f"Saved: ${self.money_saved:,.2f}  |  "
            f"API cost: ${self.misses * self.cost_per_call:,.2f}"
        )


stats = CacheStats()
cache = Ferrite(host="localhost", port=6379)

def cached_request(prompt: str, call_llm) -> str:
    key = f"llm:{hash(prompt)}"
    cached = cache.get(key)
    if cached:
        stats.hits += 1
        return cached.decode()

    stats.misses += 1
    result = call_llm(prompt)
    cache.setex(key, 3600, result)
    return result

# After running many requests:
# >>> print(stats.report())
# Requests: 50000  |  Hit rate: 74.2%  |  Saved: $74.40  |  API cost: $25.80
```

### When to Add Semantic Caching

Exact-match caching works well when prompts repeat verbatim. Switch to **semantic caching** (via `SEMANTIC.*` commands) when:

- Users rephrase the same question in different ways
- You want to match "What is Redis?" with "Explain Redis" (similarity > 0.85)
- Hit rates with exact caching plateau below 50%

Semantic caching typically raises effective hit rates from **40-50%** to **70-80%**, doubling your savings.
